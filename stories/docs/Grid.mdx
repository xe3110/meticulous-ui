# Grid

A CSS Grid layout primitive. Use `Grid` to define the track structure and `GridItem` to control individual cell placement. Both accept an `as` prop so you can render any semantic HTML element.

Import:

```jsx
import Grid, { GridItem } from 'meticulous-ui/components/Grid';
```

## Fixed Columns

Pass a number to `columns` for N equal-width `1fr` columns, or any valid CSS value for full control.

<Canvas of={GridStories.FixedColumns} />

## Responsive (minChildWidth)

`minChildWidth` sets up `repeat(auto-fit, minmax(value, 1fr))` — columns wrap automatically as the container shrinks. No media queries needed.

<Canvas of={GridStories.Responsive} />

## Template Areas

Named areas let you describe a layout as a visual map. Each string in `areas` is one row; repeated names span multiple tracks.

<Canvas of={GridStories.TemplateAreas} />

## Item Placement (spans)

Use `columnSpan` / `rowSpan` on `GridItem` to make a cell occupy multiple tracks. Use `column` / `row` for explicit `grid-column` / `grid-row` shorthand.

<Canvas of={GridStories.ItemPlacement} />

## Semantic List

Render the grid as a `<ul>` and each item as an `<li>` for correct list semantics — screen readers will announce the count and navigate by list item.

## Accessibility

- `Grid` is a pure layout primitive — it has no implicit ARIA role. When the grid represents a meaningful region, pass `as="section"` (or another landmark) and pair it with `aria-label` or `aria-labelledby`.
- For list-like grids (galleries, card decks, search results) render `as="ul"` with each `GridItem as="li"`. Screen readers will announce the item count and allow list-item navigation.
- `GridItem` forwards all HTML attributes including `aria-*`, `data-*`, and event handlers so each cell can carry its own semantics.
- Avoid relying on visual grid position alone to communicate meaning — order items logically in the DOM so keyboard and reading order matches visual order.
