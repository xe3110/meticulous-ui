# Form

A field-driven form that renders any component per field. Can be imported as `meticulous-ui/components/Form`.

The core design goal is **isolated re-renders**: when the user changes field A, field B does not re-render. Each field owns its own value and error state internally. The parent `Form` collects values through a ref, not state.

## All Components

A single form covering every supported input type: `Input` (text / email / password / URL), `Textarea`, `OtpInput`, `Dropdown` (single-select), `Selectbox` (multi-select), `RadioGroup`, `DatePicker`, `Switch`, and `Checkbox`.

## With Validation

Each field has an optional `validate` function that runs on every keystroke. Return a string to show an inline error, or `null` to clear it.

Pressing Submit without filling required fields triggers validation on all fields at once and scrolls the viewport to the first invalid one.

## With Textarea

The `component` prop accepts any React component. Mix `Input`, `Textarea`, `Dropdown`, or your own custom input — the form treats them uniformly.

## Imperative getValues()

Pass a `ref` to read current field values from outside the form (e.g. a modal footer button). The ref exposes `getValues()` which returns a `{ [fieldId]: value }` snapshot.

<Canvas of={FormStories.ImperativeGetValues} />

## Shared allProps

`allProps` at the Form level is spread onto every field component. A field-level `allProps` merges on top and can override specific keys for that field only.

## Submit behaviour

When the submit button is clicked:

1. `validate` is called on every field in order, regardless of whether the field has been touched.
2. All inline errors are shown simultaneously.
3. The viewport scrolls smoothly to the first invalid field.
4. `onSubmit` is only called if every field passes — it never fires with invalid data.

## Re-render isolation

1. Each `FormField` is wrapped in `React.memo` — it only re-renders when its own props change.
2. Value collection uses a `useRef` in Form, not state — a field change never triggers a Form re-render or a sibling re-render.
3. Validity tracking uses `useState` in Form (needed to drive the disabled button), but all FormField props remain stable references, so `React.memo` still blocks sibling re-renders.
4. Per-field `onValueChange` and `onValidityChange` callbacks are each created once and stored in ref maps — stable across every render.
5. `handleChange` inside each `FormField` has empty `useCallback` deps. All closured values (`validate`, callbacks) are accessed through refs.

The practical result: typing in one field causes exactly one component to re-render — the field you typed in.

## Accessibility

- Labels are rendered as native `<label>` elements.
- Mandatory markers use `aria-hidden="true"` so screen readers skip the `*` glyph.
- Inline error messages use `role="alert"` so they are announced immediately by screen readers.
- The submit button receives the native `disabled` attribute when `disableUntilValid` is active.
